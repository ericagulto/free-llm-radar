What this is

An aggregator: one key, one bill, many providers. A rotating subset of models is tagged ":free", and you can compare models across vendors without signing up to each one.

What it's good for

  • Comparing several models behind one API with no code changes
  • Automatic failover when one provider is down or rate-limited
  • Discovering newly released models without new signups

Caveats and red flags

  • 50 requests/day on the free tier is very tight — roughly one short session.
  • Reaching 1,000 requests/day requires a one-time $10 credit purchase, which is a purchase, not a free tier.
  • The free roster rotates weekly. Hardcoded model IDs will break, so read them from the API at runtime.

Reviews and reputation

Well covered Well covered as a product. Coverage of the free tier specifically is thinner and often out of date, because the free model list changes weekly.

What we could verify

  • Free tier is 20 req/min and 50 req/day, rising to 1,000 req/day after a one-time $10 credit purchase. Source: OpenRouter limits documentation
  • Free model IDs are suffixed ":free" and the roster changes; the API is the authoritative list. Source: OpenRouter documentation
Our take opinion

Genuinely valuable as a comparison harness and as a failover layer, and I would not build on the free allowance itself. The $10 unlock is the honest price of making it useful, and at that point you are comparing it against paid options.

Set it up

  1. Sign up at openrouter.ai — Google or GitHub login.
  2. Go to openrouter.ai/keys → Create Key. Starts with sk-or-v1-.
  3. Optional but significant: buy $10 of credit once. It is a lifetime condition, not a balance — the 20× daily limit increase is permanent even after you spend it.

Test it

# list what is free right now — do this instead of hardcoding curl https://openrouter.ai/api/v1/models \ -H "Authorization: Bearer $OPENROUTER_API_KEY" | grep -o '"[^"]*:free"' | sort -u
