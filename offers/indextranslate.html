What this is

Bilibili's Index team opened a free public API for Index-Translate-35B-A3B, a translation model built on Qwen3.5 and covering 150 languages, with terminology and formatting control. It is OpenAI-compatible at index-translate.bilibili.com/v1 and — unusually — needs no account and no API key at all. The vendor states the API is free and open, and publishes neither a rate limit nor an end date.

What it's good for

  • Translating documents, subtitles or product copy in bulk without wiring up a paid provider or even an API key
  • A drop-in replacement for the translation half of a pipeline that already speaks the OpenAI chat-completions format
  • Long-document translation — the Index family ships a dedicated long-context variant, and the API's 150-language coverage includes terminology and formatting preservation
  • A zero-setup way to check whether a translation model is good enough before paying for one

Caveats and red flags

  • It is a translation model, not a general assistant. Send it an ordinary coding or reasoning prompt and the output will be poor — that is the design, not a fault.
  • No published rate limit and no published end date. Both are genuinely unknown, so build in retry and backoff rather than assuming a quota, and do not put it on a critical path.
  • No key means no account, no support channel and no way to appeal a block. If the endpoint decides to refuse you, there is nothing to raise.
  • A third-party dependency on a mainland Chinese host with no SLA, no status page and no uptime commitment.
  • It is new — opened 4 October 2026 — so there is no track record for stability or for whether the free access is a launch promotion that quietly narrows.

Reviews and reputation

Thin independent coverage Only deal-tracker write-ups exist so far, all from early October 2026 and all restating the vendor announcement. There is no independent evaluation of translation quality, throughput or reliability, and no long-running report because the API is days old.

Our take opinion

The interesting thing here is the shape of the offer, not the model. A free, keyless, OpenAI-compatible endpoint from a major platform is vanishingly rare — it is the same frictionless pattern as Pollinations, and it costs you one environment variable to try. Judge it on the translation task it is built for: for a translation workload it is an easy yes; as a general-purpose model it is the wrong tool and will disappoint you. The absence of a published rate limit is the honest reason to treat it as a convenience rather than a dependency.

Set it up

  1. No account, no key, no card. Point any OpenAI-compatible client at https://index-translate.bilibili.com/v1.
  2. Use the model id Index-Translate-35B-A3B. There is no other model on this endpoint.
  3. Send your text with a translation instruction — e.g. 请将以下文本翻译为英语，直接输出翻译结果 — the model is tuned for translation, not open-ended chat.
  4. The vendor ships a zero-dependency script for a quick check: python inference/llm/call_api.py "你好，世界" --target en.

Test it

curl https://index-translate.bilibili.com/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{"model":"Index-Translate-35B-A3B","messages":[{"role":"user","content":"请将以下文本翻译为英语，直接输出翻译结果，不要进行任何解释。\n\n你好，世界。"}]}'
